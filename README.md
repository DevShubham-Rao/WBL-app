# Timestamp — iOS workplace visit tracker

Timestamp is a SwiftUI iPhone app for work-based learning teachers, derived from the supplied WBL-app project. This is the **source code**, not an already-signed IPA. The GitHub Actions build workflows, `builder.json`, XcodeGen manifest, iOS target, and `WBLTracker` scheme are preserved.

## New in Timestamp

- App display name and dashboard branding changed to **Timestamp**.
- **Light Blue + white** default style, with additional green, plum, and orange themes in Settings. Appearance defaults to Light and can be switched to Dark or Match iPhone. Themes and appearance persist across launches.
- The previous **P-road icon/logo** is retained, since no replacement logo was supplied.
- **Automatic graduation-year deletion** is ON by default. A student with graduation year `2028` becomes due for deletion on **July 1, 2029**. The app does not assume an exact graduation date. Confirm the cutoff with a school/district records administrator before handling real student records.
- With auto-delete enabled, the app checks **after its one-time privacy notice is acknowledged, on subsequent launches, when returning to the foreground, after importing/editing students, and before export**. There is **no background deletion while the app is closed**; overdue records remain until the next check.
- The first launch displays a **student privacy notice** explaining the teacher's responsibility. Users can either acknowledge and enable cleanup or choose **Review or export older records first**, which turns auto-delete off until they re-enable it in Settings.
- Disabling auto-delete requires confirmation. Settings and Data & Exports explain the user's responsibility to transfer school-required records to an authorized location and manually delete records when auto-delete is off.
- Individual student profiles show the retention cutoff. A missing/invalid graduation year is called out in Settings: such records are NOT deleted automatically.

### What automatic deletion removes

When an eligible student passes their cutoff, Timestamp removes their student roster record, employer/address/phone information, notes, and visit history from its **local JSON database**. Any trip/session containing that student is also removed, because its route, mileage or stops could reveal student data. This may also erase **shared trip mileage records** involving other students; those other students' standalone visit history is kept, with links to deleted trips cleared.

**Important:** Deletion is permanent for the locally retained dataset and may occur on the first run of the update if existing records are overdue. Back up or securely transfer any school-required information before enabling this feature. Deleting from the app **does not delete exports, shared CSV/ZIP files, device backups, cloud backups, or data held by external mapping providers**. Regular file deletion is not a guarantee of forensic erasure. The app does not certify FERPA compliance; consult your school's policies and authorized records staff.

### Existing-data compatibility

- The existing `com.buildertest.wbltracker` bundle ID is preserved to support in-place updates and retention of app data. Keep the same signing/install method where possible.
- Records are still loaded from the local `wbl-visits.json` file, including migration from legacy date-only visits to typed visits. Existing timestamps are preserved if the record is not due for deletion.
- The Xcode project generated by XcodeGen is now **`Timestamp.xcodeproj`**, while the build scheme/target remain **`WBLTracker`**.
- Settings from older VisitPath versions for the theme are migrated where possible.

## Current feature set

| Screen | Features |
|---|---|
| Home | Student and visit counts, active session, checklist of workplace visits |
| Students | Add/edit/import via `.csv`, `.tsv`, `.xlsx`; search and sort; visit count and per-student history/notes |
| Plan | Select students, visit type (in person / Zoom / phone / message), optimize only in-person route |
| Mileage | Saved trips, visit details and edited reimbursement mileage |
| Data | Export independent reports for any date range, or all currently retained records as ZIP; full reset |
| Settings | Theme, Light/Dark/Match iPhone, auto-delete option and student privacy responsibility guidance |

## Spreadsheet import

Students → Import supports `.xlsx`, `.csv`, `.tsv`, and pasted CSV. For Google Sheets, download as Excel `.xlsx` or CSV first. Use columns: `First Name, Last Name, Graduation Year, Grade, Employer Name, Employer Address, Phone Number`.

## Building

1. Extract the ZIP. Upload the **contents** of `WBL-app-main/` to the root of the existing GitHub repository.
2. Check the repository configuration in `builder.json` if your builder uses it.
3. On macOS, run `xcodegen generate`; this creates `Timestamp.xcodeproj`. Build using the **`WBLTracker`** scheme, iOS 17.2 or newer.
4. GitHub Actions can compile an unsigned IPA; installing on an iPhone requires appropriate Apple signing/provisioning.

The source uses MapKit, CoreLocation and the Swift Package Manager dependency `ZIPFoundation`. Route mileage is an estimate, not GPS-tracked reimbursement distance. Student information and notes remain in local app storage without app-specific encryption, account authentication or cloud sync. Exported records must be safeguarded under school policy.

### Validation

`swiftc -frontend -parse` passes for all Swift files; Foundation model/retention policy tests cover the expiration date, invalid years, unrelated records and linked-trip removal. ZIP file integrity is checked. A **complete Xcode/iOS SDK build and iPhone device test have not been performed** here.
